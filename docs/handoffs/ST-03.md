# ST-03: WebSocket info frame protocol

## Spec

**What:** When `image/meta` changes, update `AppState` and broadcast a fresh JSON info frame to all connected WebSocket clients; `ViewerCanvas` parses that frame and propagates `pixel_format`/`width`/`height` to `ImageViewer` via a new `onStreamInfoChange` prop.

**Why:** Clients that connect after a format change currently receive a stale info frame built from CLI hints; the pixel inspector and status bar show wrong format/dimensions until the Tauri `image-meta-changed` event fires separately.

**Files touched:**
- `apps/genicam-ws-streamer/src/ws.rs` — replace `AppState.info: StreamInfo` with `info: Arc<RwLock<StreamInfo>>`; add `info_tx: watch::Sender<StreamInfo>`; update `handle_socket` to await both the info watch and the frame watch; add `StreamInfo::from_image_meta` constructor; derive `serde::Serialize` on `StreamInfo`; replace hand-rolled `to_json` with `serde_json::to_string`
- `apps/genicam-ws-streamer/src/zenoh_source.rs` — after writing `shared_meta`, also call `info_tx.send(StreamInfo::from_image_meta(&meta))` to trigger broadcast to existing clients
- `apps/genicam-ws-streamer/src/main.rs` — thread an `Arc<RwLock<StreamInfo>>` and `info_tx`/`info_rx` watch pair through `AppState` and `zenoh_source::run`; remove the `TODO(ST-03)` comment
- `ui/genicam-studio-ui/src/components/ImageViewer/ViewerCanvas.tsx` — handle text messages from WebSocket: parse JSON, validate `type === "info"`, call `onStreamInfoChange` prop
- `ui/genicam-studio-ui/src/components/ImageViewer/ImageViewer.tsx` — add `onStreamInfoChange` handler; override `imageMeta` from the info frame when it arrives ahead of the Tauri `image-meta-changed` event (local state merge, not a new source of truth)

**Key decisions:**
- Use a second `watch::Sender<StreamInfo>` (not a broadcast channel) for info propagation; this keeps the existing `watch::Sender<Bytes>` for frames untouched and lets `handle_socket` `select!` on both channels with no extra synchronisation primitive.
- `StreamInfo` gets `#[derive(Serialize)]` and the `pixel_format` field changes from `&'static str` to `String` so it can hold the serde output of `PixelFormat` without a static lifetime; `encoding` stays `&'static str` (always `"BMP"` today).
- The frontend treats the WebSocket info frame as an early-arrival hint only — `ImageViewer` still consumes `imageMeta` from the Tauri `image-meta-changed` event as the canonical source. When both arrive the Tauri value wins (it is already in state via `imageMeta` prop).
- `onStreamInfoChange` is optional (`?`) on `ViewerCanvas` to keep the component backward-compatible.

**Unit tests required:**
- `fn test_stream_info_to_json_mono8` in `apps/genicam-ws-streamer/src/ws.rs` — verifies `StreamInfo::from_image_meta` round-trips to the expected JSON shape for Mono8
- `fn test_stream_info_to_json_rgb8` in `apps/genicam-ws-streamer/src/ws.rs` — verifies `pixel_format` field is `"RGB8"` (serde output of `PixelFormat::RGB8`)
- `fn test_stream_info_to_json_unknown` in `apps/genicam-ws-streamer/src/ws.rs` — verifies `PixelFormat::Unknown` serialises without panicking

## Implementation

All changes implemented:
- `main.rs`: replaced `StreamInfo::mono8_bmp` + old `AppState` with `watch::channel(initial_info)` + new `AppState { info_tx }`; `zenoh_source::run` now receives `info_tx`; removed `TODO(ST-03)` comment. Also added `serde = { version = "1", features = ["derive"] }` to `Cargo.toml` (was missing).
- `zenoh_source.rs`: fixed borrow-after-move by computing `stream_info` before the `meta` move into `shared_meta`.
- `ws.rs` and `zenoh_source.rs`: already updated (done before this session).
- `ViewerCanvas.tsx`: text WebSocket messages are now parsed; `onStreamInfoChange` optional prop added; `StreamInfoFrame` type exported.
- `ImageViewer.tsx`: `wsStreamInfo` local state merges WS info frame as early hint; Tauri `imageMeta` prop wins when both present.
