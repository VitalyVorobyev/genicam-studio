# UX-06: Responsive Layout

## Spec

**What:** Add drag-to-resize splitter handles to the two main split panes (device sidebar ↔ main area, and feature-browser tree ↔ detail panel), enforce minimum sizes, and persist splitter positions across sessions via localStorage.
**Why:** Allows engineers to allocate screen space to the pane they need most (e.g., wider tree on large monitors, wider detail panel when editing), which is a standard expectation for professional desktop tooling.

**Files touched:**
- `ui/genicam-studio-ui/src/components/Layout/useSplitter.ts` — new: exported `clampSplitter` pure function + `useSplitter` hook (pointer-capture drag, min/max clamp, localStorage persistence)
- `ui/genicam-studio-ui/src/components/Layout/useSplitter.test.ts` — new: unit tests for `clampSplitter`
- `ui/genicam-studio-ui/src/components/Layout/AppLayout.tsx` — call `useSplitter` for device sidebar width; add `<div {...sidebarSplitterProps} />` between sidebar and main
- `ui/genicam-studio-ui/src/components/FeatureBrowser/FeatureBrowserPage.tsx` — call `useSplitter` for tree pane width; inject into `feature-browser__body` via inline `gridTemplateColumns` style; add splitter handle between panes
- `ui/genicam-studio-ui/src/styles/components.css` — `.pane-splitter` (8px wide, col-resize cursor, accent ::after highlight on hover/drag)

**Key decisions:**
- Drag handlers are attached to `document` (not the handle element) so fast mouse moves don't lose the drag; they are removed on `pointerup` to avoid memory leaks
- Event listeners are registered inline inside `onPointerDown` (closure pattern) to avoid circular `useCallback` dependencies and stale-closure issues
- `clampSplitter` is extracted as a pure, exportable function so it can be unit-tested independently of the hook's React state
- Splitter positions are persisted to localStorage on `pointerup` (not on every move) to avoid excessive writes
- The feature-browser body grid goes from `280px 1fr` → `{treeWidth}px 8px 1fr`; the splitter div occupies the 8px column between the two panes (no DOM restructuring needed)
- `useSplitter` is called unconditionally (respects Rules of Hooks); the sidebar splitter is only rendered when `isTauri()` is true
- Min sizes: device sidebar 160px, tree pane 160px; Max: device sidebar 420px, tree pane 600px
