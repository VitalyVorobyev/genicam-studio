# MS-13: Bulk Node Read Queryable

## Spec

**What:** Add a `nodes/bulk/read` Zenoh queryable to the mock service that returns multiple node values in a single round-trip; add `BulkReadRequest`/`BulkReadResponse` types to `genicam_zenoh_api`.
**Why:** Reduces UI initialization latency — one GET instead of N sequential GETs to seed the live-value cache for an entire SFNC group. Prerequisite for TB-02.

**Files touched:**
- `crates/genicam_zenoh_api/src/lib.rs` — add `BulkReadRequest`, `BulkReadResponse`, `keys::nodes_bulk_read`
- `apps/genicam-mock-service/src/nodes.rs` — add `run_bulk_read_queryable`
- `apps/genicam-mock-service/src/state.rs` — remove `#[allow(dead_code)]` from `NodeStore::get`
- `apps/genicam-mock-service/src/main.rs` — spawn `run_bulk_read_queryable` task
- `docs/zenoh-api.md` — document new key

**Key decisions:**
- Unknown node names silently omitted from response (not an error) — consistent with best-effort SFNC read semantics
- Static key `nodes/bulk/read` with JSON body (not wildcard) — avoids key-expression length limits, consistent with `acquisition/control`
- Per-entry response shape identical to `nodes/{name}/value` — client reuses existing deserialization

**Unit tests required:** None — queryable handler is async; `NodeStore::get` tested implicitly via bulk handler

**CHANGELOG entry:** `- MS-13/ZA-02: Bulk node read queryable (nodes/bulk/read) and shared BulkReadRequest/BulkReadResponse types`
