# UX-07: Loading & Error States

## Spec

**What:** Add a toast notification system (auto-dismiss, color-coded by level, top-right position) and a skeleton shimmer class applied to the Feature Browser tree pane while XML is loading.
**Why:** Users currently get no immediate visual feedback on connection success/failure or acquisition state changes unless they look at the Diagnostics tab.

**Files touched:**
- `ui/genicam-studio-ui/src/context/ToastContext.tsx` — new: `ToastProvider`, `useToast` hook, exported `formatToastDuration` pure function
- `ui/genicam-studio-ui/src/context/ToastContext.test.ts` — new: unit tests for `formatToastDuration`
- `ui/genicam-studio-ui/src/components/Layout/ToastContainer.tsx` — new: renders the toast list (fixed position, aria-live)
- `ui/genicam-studio-ui/src/components/Layout/AppLayout.tsx` — wrap with `ToastProvider`; call `addToast()` at connect success/error, acquisition start/stop/error; render `<ToastContainer />`; remove the now-redundant `connectError` state strip
- `ui/genicam-studio-ui/src/components/FeatureBrowser/FeatureBrowserPage.tsx` — apply `browser-status--loading-shimmer` class (shimmer) to the status strip when loading
- `ui/genicam-studio-ui/src/styles/components.css` — toast CSS (`.toast-container`, `.toast`, `.toast--*` variants, slide-in animation); shimmer keyframe + `.browser-status--loading-shimmer`

**Key decisions:**
- `ToastContext` is separate from `AppLogContext` — log entries go to the Diagnostics tab (verbose), toasts go to the user-facing overlay (selective); avoid spamming every `log()` call as a toast
- `ToastProvider` wraps `AppLayoutInner` (inside `AppLogProvider`) so both contexts are available inside the same subtree
- Auto-dismiss is done with `setTimeout` stored in a `Map<id, TimerId>` ref — prevents stale closure issues and allows clearing timers if a toast is manually dismissed before expiry
- Max 5 toasts at once (oldest is removed first when the limit is reached)
- `connectError` state + its `.status--error` strip are removed from `AppLayout` — the toast replaces it for user feedback, and the Diagnostics log still records it
- Skeleton shimmer on the `browser-status` strip when `status.kind === "loading"` — minimal change, no new components

**Unit tests required:**
- `test_formatToastDuration_info` in `ToastContext.test.ts` — "info" → 3000
- `test_formatToastDuration_success` in `ToastContext.test.ts` — "success" → 3000
- `test_formatToastDuration_warning` in `ToastContext.test.ts` — "warning" → 5000
- `test_formatToastDuration_error` in `ToastContext.test.ts` — "error" → 6000
