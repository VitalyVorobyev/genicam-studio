# IV-10: Section persistence

## Spec

**What:** Save the expand/collapse state of each Image Viewer sidebar section to localStorage, keyed per camera model, so state survives re-renders and is camera-specific.

**Why:** IV-09 conditionally shows/hides sections, which unmounts and remounts `SidebarSection` and discards its internal `useState` open flag; persistence removes that regression and honours ADR-006.

**Files touched:**
- `ui/genicam-studio-ui/src/components/ImageViewer/useSectionPersistence.ts` — new hook; reads/writes per-section open state to localStorage under key `iv-sections-{cameraModel}`
- `ui/genicam-studio-ui/src/components/ImageViewer/SidebarSection.tsx` — add optional `onToggle?: (open: boolean) => void` prop; call it after each internal state flip
- `ui/genicam-studio-ui/src/components/ImageViewer/ControlSidebar.tsx` — accept new `cameraModel: string | null` prop; wire `useSectionPersistence`; pass `defaultOpen` and `onToggle` into each `SidebarSection`
- `ui/genicam-studio-ui/src/components/ImageViewer/ImageViewer.tsx` — thread `cameraModel` down to `ControlSidebar` (derive from `ConnectionState.model` already available via `AppLayout` → `ImageViewer`)

**Key decisions:**
- The localStorage key is `"iv-sections-{cameraModel}"` where `cameraModel` is the string from `ConnectionState.model` (e.g., `"acA1920-155uc"`). When `cameraModel` is `null` (no device connected), a fallback key `"iv-sections-__default__"` is used so state is never silently dropped during disconnect/reconnect cycles.
- `defaultOpen` from `sfnc-groups.json` is used only when no persisted entry exists for a given section id — it remains the authoritiative first-run default.
- The raw localStorage value is a compact JSON object mapping section id → boolean (e.g., `{"acquisition_control":true,"image_format":false}`). A single `JSON.parse` per mount is cheap; individual writes on each toggle are instant.
- `SidebarSection` stays self-contained for open/close animation — it keeps its own `useState` with `defaultOpen` as the seed; `onToggle` is an optional side-effect callback only. This preserves the component's independence.
- `cameraModel` is NOT passed through `ImageViewer` via a new top-level prop from `AppLayout`. Instead, `ImageViewer` already receives `deviceName` (the connected device name string). However, `deviceName` is `device_name`, not `model`. The blueprint threads `model` (from `ConnectionState.model`) via a new optional `cameraModel?: string` prop on `ImageViewer`, mirroring how `deviceName` is already threaded.

**Unit tests required:**
- `fn test_read_stored_sections_empty` in `useSectionPersistence.ts` helper test — verifies empty localStorage returns `{}` record
- `fn test_read_stored_sections_malformed` — verifies a corrupted JSON string returns `{}` rather than throwing
- `fn test_build_storage_key_with_model` — verifies key is `"iv-sections-acA1920"` when model is `"acA1920"`
- `fn test_build_storage_key_null_model` — verifies key is `"iv-sections-__default__"` when model is `null`
