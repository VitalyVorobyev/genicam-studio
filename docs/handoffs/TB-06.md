# TB-06: Error Recovery on Disconnect

## Spec

**What:** On unexpected device disconnect (`DeviceStatus { connected: false }` from the camera service), the Tauri backend performs full cleanup (abort subscriber tasks, stop streamer, clear node cache) and emits a new `disconnect-reason` Tauri event; the UI displays a reconnect prompt banner in the Device Sidebar.

**Why:** Without cleanup, zombie subscriber tasks continue firing and the streamer child process keeps running against a lost device; the reconnect prompt gives users a one-click path back without restarting the app.

**Files touched:**
- `apps/genicam-studio-tauri/src-tauri/src/state/device_state.rs` — add `DisconnectReason` struct (serializable, backend→frontend event payload)
- `apps/genicam-studio-tauri/src-tauri/src/commands/device.rs` — add `do_emergency_disconnect` async fn; update `spawn_status_sub` to call it and `break` the receive loop on disconnect; add `DisconnectReason` to imports; add unit tests
- `ui/genicam-studio-ui/src/device/types.ts` — add `DisconnectReason` and `StreamerStatus` interfaces
- `ui/genicam-studio-ui/src/device/useDevice.ts` — subscribe to `disconnect-reason` event; expose `disconnectReason` state; reset on connect
- `ui/genicam-studio-ui/src/components/Layout/AppLayout.tsx` — track `lastConnectedDeviceId`; clear `externalModel` on disconnect; pass `disconnectReason` and `lastConnectedDeviceId` to `DeviceSidebar`
- `ui/genicam-studio-ui/src/components/DeviceSidebar/DeviceSidebar.tsx` — replace plain error div with reconnect prompt banner (message + "Reconnect" button calling `onConnect(lastConnectedDeviceId)`)
- `docs/zenoh-api.md` — add `disconnect-reason` row to the Tauri Events table
- `CHANGELOG.md` — add entry under `[Unreleased]`

**Key decisions:**
- `do_emergency_disconnect` is placed in `commands/device.rs` (not a new file) because it reuses the existing `abort_sub_tasks`, `stop_acquisition_child`, and `emit_connection_state` helpers already defined there; keeping it co-located avoids a new module for a single function.
- The status subscriber task calls `break` after `do_emergency_disconnect` for clean self-termination; `abort_sub_tasks` drains the `sub_tasks` vec, so the current task is not in that list and must exit itself.
- Prompt-only reconnect (no auto-retry at the Rust level): the backlog explicitly says "reconnect prompt"; silent auto-retry risks confusing users who deliberately powered off the camera.
- `externalModel` is reset to `null` on disconnect so the Feature Browser shows an empty state rather than stale data. (See Open Question 3 if stale/read-only mode is preferred instead.)

**Unit tests required:**
- `fn test_disconnect_reason_serializes_fields` in `commands/device.rs` — verifies `DisconnectReason { message, device_id }` serializes both fields correctly with serde_json
- `fn test_disconnect_reason_empty_message` in `commands/device.rs` — verifies `message: ""` serializes as empty string (not absent)
