# IV-04: Image Format Section

## Spec

**What:** Add an "Image Format" accordion section to the Image Viewer control sidebar, with controls for PixelFormat (enum select), Width/Height/OffsetX/OffsetY (integer slider + text input), and optional BinningHorizontal/BinningVertical selects (shown only when those nodes exist in the UiGraph).

**Why:** Completes the M3 Image Viewer milestone; gives engineers direct ROI and pixel format control without opening the Feature Browser.

**Files touched:**
- `ui/genicam-studio-ui/src/components/ImageViewer/imageFormatUtils.ts` — new file: pure helpers for integer step resolution, pixel dimension label formatting, and dynamic OffsetX/OffsetY max derivation
- `ui/genicam-studio-ui/src/components/ImageViewer/ImageFormatSection.tsx` — new file: the full Image Format accordion body component
- `ui/genicam-studio-ui/src/components/ImageViewer/ControlSidebar.tsx` — replace the placeholder `<p>` in the "Image Format" `SidebarSection` with `<ImageFormatSection ...>`
- `ui/genicam-studio-ui/src/styles/components.css` — add `.img-format-section`, `.if-enum-row`, and `.binning-row` CSS blocks
- `CHANGELOG.md` — add IV-04 entry under `[Unreleased]`

**Key decisions:**
- `extractNumericConstraints` and `clampValue` already exist in `exposureGainUtils.ts` and are directly reusable; `imageFormatUtils.ts` imports and re-exports them rather than duplicating. New helpers added there cover: integer step resolution (`resolveIntStep`), pixel dimension label formatting (`formatPixelDimension`), and dynamic offset max derivation (`deriveOffsetMax`).
- Dynamic OffsetX/OffsetY max: ZA-06 (constraints in value updates) is not yet done, so `NodeValueUpdate` carries no constraint payload. The correct approach is to compute `max = SensorWidth - Width` and `max = SensorHeight - Height` from live values at render time, mirroring the service-side MS-12 logic. The UiGraph constraint for OffsetX/OffsetY (4095/3071 from the fixture) serves as the hard ceiling fallback when live Width/SensorWidth are absent.
- BinningHorizontal and BinningVertical are Integer nodes in the mock fixture (min 1, max 4, inc 1) but are treated as small-integer selects (1–4 as discrete options) rather than continuous sliders, since binning factors are always small integers. If future cameras expose them as Enumeration nodes, the node kind check handles that gracefully.
- Integer slider `step` attribute: use `inc` from UiGraph constraints when `inc > 0`, otherwise fall back to `1`. This matches the task requirement and avoids fractional steps on integer nodes.
- Write on pointer-up (not on every drag tick) using the same `useRef` dragging guard used in `ExposureGainSection`. Write on text input blur with clamp.
- No props changes to `ImageViewer` — `externalModel` and `liveValues` are already threaded through `ControlSidebar`.

**Unit tests required:**
- `imageFormatUtils.test.ts`:
  - `test_resolveIntStep_positive_inc` — `resolveIntStep({inc: 4})` returns `4`
  - `test_resolveIntStep_zero_inc` — `resolveIntStep({inc: 0})` returns `1`
  - `test_resolveIntStep_undefined` — `resolveIntStep(undefined)` returns `1`
  - `test_formatPixelDimension` — `formatPixelDimension(1920)` returns `"1920 px"`
  - `test_deriveOffsetMax_from_live` — with `SensorWidth=4096`, `Width=1920`, returns `2176`
  - `test_deriveOffsetMax_clamp_zero` — with `Width > SensorWidth`, returns `0`
  - `test_deriveOffsetMax_fallback` — when live values absent, returns UiGraph max
