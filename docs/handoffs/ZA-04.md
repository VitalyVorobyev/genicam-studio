# ZA-04: Inline Frame Header in Image Payload

## Spec

**What:** Defines and implements a 16-byte binary frame header prepended to every raw pixel buffer published on the `genicam/devices/{device_id}/image` Zenoh key, making each frame self-describing (magic, version, pixel format discriminant, width, height, sequence number).

**Why:** Eliminates subscription-ordering races between `image` and `image/meta` keys, which would otherwise cause the multi-format streamer (ST-02) to misinterpret frame buffers when a format change is in flight.

**Files touched:**
- `crates/genicam_zenoh_api/src/frame_header.rs` — new module: `FrameHeader` struct, `encode`/`decode`, `FrameHeaderError`, `FRAME_MAGIC`, `HEADER_SIZE`, and format discriminant table functions `pixel_format_to_u8` / `u8_to_pixel_format`
- `crates/genicam_zenoh_api/src/lib.rs` — add `pub mod frame_header;` and re-export `FrameHeader`, `FrameHeaderError`, `FRAME_MAGIC`, `HEADER_SIZE`
- `crates/genicam_zenoh_api/Cargo.toml` — add `thiserror = "1"` dependency
- `apps/genicam-mock-service/src/acquisition.rs` — prepend `FrameHeader` to every `session.put(&image_key, …)` call in the ticker arm
- `apps/genicam-ws-streamer/src/zenoh_source.rs` — decode `FrameHeader` from front of each frame payload; use header fields for format/size validation
- `docs/zenoh-api.md` — document new binary frame header layout under the `image` key section
- `CHANGELOG.md` — add entry under `[Unreleased]`

**Key decisions:**
- **Inline header over separate key** (recorded in `docs/backlog.md` line 8): embedding the header directly in the image payload means every frame is self-describing with no dependency on `image/meta` subscription ordering; the `image/meta` key is retained for the Tauri app and for streamer encoder rebuild on dimension changes.
- **Binary encoding, not JSON**: 16-byte fixed-size layout (magic + version + format u8 + width u32 + height u32 + seq u32, all little-endian) keeps overhead to 16 bytes per frame with zero parsing cost beyond a `memcpy`.
- **Stable discriminant table**: `pixel_format_to_u8` / `u8_to_pixel_format` use a fixed integer code per variant (codes only appended, never reordered); any unknown code maps to `PixelFormat::Unknown`.
- **Breaking change to `image` payload**: any external camera service consuming or publishing to this key must update. Both affected consumers (mock service, streamer) are in this repo and updated in the same commit.

**Unit tests required:**
- `fn test_encode_decode_roundtrip_mono8` in `frame_header.rs` — full encode then decode, asserts all fields match and remaining pixel slice is empty
- `fn test_encode_produces_correct_magic` in `frame_header.rs` — asserts first two bytes equal `[0x46, 0x47]`
- `fn test_encode_length` in `frame_header.rs` — asserts returned Vec length == `HEADER_SIZE` (16)
- `fn test_decode_buffer_too_short` in `frame_header.rs` — 15-byte buffer returns `Err(TooShort)`
- `fn test_decode_bad_magic` in `frame_header.rs` — wrong magic bytes returns `Err(BadMagic)`
- `fn test_decode_unsupported_version` in `frame_header.rs` — version=2 returns `Err(UnsupportedVersion(2))`
- `fn test_decode_returns_pixel_slice` in `frame_header.rs` — header + 100 pixel bytes; asserts returned slice len == 100
- `fn test_decode_with_pixel_data_roundtrip` in `frame_header.rs` — Mono16 variant encode + decode + pixel slice verify
- `fn test_pixel_format_roundtrip_all_known` in `frame_header.rs` — all named non-Unknown variants survive `u8_to_pixel_format(pixel_format_to_u8(&pf)) == pf`
- `fn test_pixel_format_unknown_code` in `frame_header.rs` — code `0xFF` maps to `PixelFormat::Unknown`
- `fn test_pixel_format_unknown_to_u8` in `frame_header.rs` — `pixel_format_to_u8(&PixelFormat::Unknown) == 0`
