# IV-12: Pixel Inspector (Crosshair)

## Spec

**What:** Adds a hover crosshair over the image canvas that tracks mouse position and displays image-space pixel coordinates plus the raw pixel value in the status bar.

**Why:** Machine vision engineers need to inspect individual pixel values (check linearity, verify no clipping, diagnose banding) without leaving the Image Viewer.

**Key decisions:**
- **Option B for pixel sampling (raw Uint8Array ref, not getImageData):** `getImageData` loses bit depth for Mono16 because `createImageBitmap` tone-maps before writing to canvas. Storing `new Uint8Array(event.data)` in a ref on every WebSocket message is O(1) and preserves the raw bytes. Note: until ST-02 (multi-format BMP encoder) is complete, the streamer delivers BMP-encoded frames, so Mono16 bytes in the ref are actually 8-bit downsampled BMP pixel data. A `// TODO(ST-02)` comment must mark this limitation.
- **SVG overlay for crosshair:** Composable, no extra render loop, trivially pointer-events:none. Two `<line>` elements update via React state on `mousemove`. The SVG fills the wrap div absolutely; it does not interfere with zoom/pan pointer events.
- **`pixelFormat` from `liveValues`, not TB-01:** TB-01 (Tauri `image-meta-changed` event) is not yet implemented. The `PixelFormat` SFNC node live value is already subscribed to and available in `liveValues`. Derive with `liveValues.get("PixelFormat")?.value as string`. The string matches the Rust `PixelFormat` serde variant names used in `samplePixel`.
- **Status bar for pixel info, not tooltip:** Simpler, always visible, consistent with existing FPS/resolution display. Coordinates and value appear as additional `·`-separated segments only when mouse is over the image.
- **Coordinate transform uses wrap-relative mouse coords:** Mouse position is measured from wrap div top-left (via `getBoundingClientRect`). The inversion formula accounts for center-anchored canvas placement (`left:50%; top:50%`), pan offset, and CSS scale ratio (`scale/fitScale`). See blueprint for the exact derivation.

**Correctness verification (all pass):**
- `mouseToImageCoords` formula matches spec exactly: `pixX = floor(((mx - boxW/2 - panX) / s) / fitScale + imgW/2)` where `s = scale/fitScale`; implementation divides by `s` then by `fitScale` yielding the same result.
- Returns `null` when `fitScale <= 0`, `imgW <= 0`, `imgH <= 0`, or coords outside `[0,imgW) x [0,imgH)`.
- Mono16 reads 2 bytes little-endian: `bytes[idx] | (bytes[idx+1] << 8)`. Bounds check uses `idx + 1 >= bytes.length`.
- RGB8 reads `r=bytes[idx], g=bytes[idx+1], b=bytes[idx+2]`. Correct.
- BGR8 swaps correctly: `r=bytes[idx+2], g=bytes[idx+1], b=bytes[idx]`. Confirmed against test.
- `lastFrameRef.current = new Uint8Array(event.data)` is assigned on line 101 of `ViewerCanvas.tsx`, before the async `createImageBitmap` call on line 104. Ordering is correct.
- `CrosshairOverlay` has `pointerEvents: "none"` set inline in JSX and also in `.iv-crosshair` CSS rule. Does not block zoom/pan.
- `onMouseLeave` calls both `setWrapMouse(null)` (clears crosshair position) and `onPixelHover?.(null)` (clears pixel info in status bar).
