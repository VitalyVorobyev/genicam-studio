# IV-11: Zoom and Pan

## Spec

**What:** Adds mouse-wheel zoom (cursor-centered), click-drag pan, and double-click reset-to-fit to the Image Viewer canvas, with a live zoom level readout in the toolbar.

**Why:** Lets engineers inspect fine details of the live image frame; also establishes the zoom/pan state object that IV-12 (pixel inspector) needs to map mouse position to image pixel coordinates.

**Files touched:**
- `ui/genicam-studio-ui/src/components/ImageViewer/zoomPanUtils.ts` — pure helper functions: `computeFitScale`, `clampZoom`, `clampPan`, `zoomAroundPoint`, `formatZoomLabel`
- `ui/genicam-studio-ui/src/components/ImageViewer/zoomPanUtils.test.ts` — unit tests for all five pure functions
- `ui/genicam-studio-ui/src/components/ImageViewer/useZoomPan.ts` — React hook owning `{ scale, panX, panY }` state, returning event handlers and `ZoomPanState`
- `ui/genicam-studio-ui/src/components/ImageViewer/ViewerCanvas.tsx` — attaches zoom/pan handlers; applies CSS `transform` on canvas; emits `onZoomPanChange` callback; tracks box size via `ResizeObserver`
- `ui/genicam-studio-ui/src/components/ImageViewer/ViewerToolbar.tsx` — accepts `zoomLabel?: string` prop; renders `.iv-toolbar__zoom` badge
- `ui/genicam-studio-ui/src/components/ImageViewer/ImageViewer.tsx` — lifts `zoomLabel` state; threads `onZoomPanChange` down to canvas and `zoomLabel` up to toolbar
- `ui/genicam-studio-ui/src/styles/components.css` — adds `.iv-toolbar__zoom`, `.iv-canvas-wrap--grab`, `.iv-canvas-wrap--grabbing`, `touch-action: none` on wrap
- `CHANGELOG.md` — entry under `[Unreleased]`

**Key decisions:**

- **Hook + CSS transform, not canvas redraw.** `useZoomPan` owns state; transform is applied via `canvas.style.transform` (CSS compositing) so zoom/pan cost zero canvas redraws. The 2D draw call fires only when a new WebSocket frame arrives.

- **Lift state to `ImageViewer` via callback, not ref.** `ViewerCanvas` calls `onZoomPanChange(state)` so `ImageViewer` can pass `zoomLabel` to `ViewerToolbar` without coupling the toolbar directly to the canvas. IV-12 can subscribe to the same callback for pixel coordinates.

- **Native wheel listener for `preventDefault`.** React synthetic wheel events cannot prevent page scroll because the listener is passive by default. A `useEffect`-attached native `addEventListener("wheel", handler, { passive: false })` on the wrap div handles `preventDefault`; state mutation is done via refs (not React state) inside the native handler to avoid stale closures, with a single `setState` call to trigger re-render.

- **`ZoomPanState` includes `fitContainResult`** (the `FitContainResult` from `fitContain`) so IV-12 can compute `imageRect` without repeating the fit calculation.

- **Max zoom: 16×.** Exported as `MAX_ZOOM = 16` constant from `zoomPanUtils.ts`.

- **Pan clamping keeps at least 40 px of image visible** on each edge; resets to `(0, 0)` automatically when zoom returns to fit level.

- **Canvas CSS centering strategy.** Replace the current `left`/`top` pixel offsets from `fitContain` with `left: 50%; top: 50%; transform: translate(-50%, -50%) translate(panX, panY) scale(scale/fitScale)` to avoid asymmetric letterbox shift issues. This makes the transform origin unambiguously the canvas center.

### Important Issues

**I-1. `clampPan` does not satisfy the "returns {0,0} at fitScale" spec invariant**

File: `ui/genicam-studio-ui/src/components/ImageViewer/zoomPanUtils.ts` lines 34–61

The review checklist states: "clampPan returns `{0, 0}` when scale equals fitScale (no pan at fit level)." The implementation does not enforce this. At `scale === fitScale`, `ratio = 1`, `dispW = imgW * fitScale`, and `maxPanX = max(0, (dispW - 40) / 2)`. For any image wider than 40 CSS pixels at fit scale this is non-zero. Example: 640×480 image in 800×600 box yields `fitScale = 1.0`, `maxPanX = 300`, `maxPanY = 220` — the image can be dragged 300 px sideways even at fit zoom.

The test `test_clampPan_at_fit_scale_returns_zero` is also misnamed: it asserts `result.panX ≈ expectedMaxX` (i.e. the clamped-but-non-zero value), not zero. The test passes because it matches the implementation, but the test name and spec claim are both incorrect.

UX impact: users can pan the image at fit zoom, leaving it off-centre until the next double-click reset. This is likely undesirable. Fix: add a short-circuit at the top of `clampPan` — if `Math.abs(scale - fitScale) < 1e-9`, return `{ panX: 0, panY: 0 }`. Update the test assertion to `expect(result.panX).toBe(0)`.

Confidence: 95%.

**I-2. Hardcoded `999px` literal in new CSS rule (no token)**

File: `ui/genicam-studio-ui/src/styles/components.css` line 1162 (`border-radius: 999px` in `.iv-toolbar__zoom`).

The review invariant is "No hardcoded hex or pixel literals in new CSS — only `var(--*)` tokens." `tokens.css` defines `--radius-sm` through `--radius-lg` (3 px–8 px) but has no pill/capsule token. The `999px` trick for a pill shape is a design decision that should be captured as `--radius-pill: 999px` in `tokens.css` and referenced as `border-radius: var(--radius-pill)`.

Confidence: 90%.

---

### Minor Issues

**M-1. `buildTransform` is a new pure function with no unit tests**

File: `ui/genicam-studio-ui/src/components/ImageViewer/zoomPanUtils.ts` lines 104–112

`buildTransform` is exported, synchronous, and has no side effects (pure function). Review checklist C requires at least one `#[cfg(test)]`-equivalent test per new pure function. The test file imports only the five functions listed in the spec; `buildTransform` is unimported and untested. Because `buildTransform` was listed in the implementation notes as an additive deviation (not in the original five), this is Minor rather than Important — but the CSS transform string it produces is load-bearing for the entire zoom/pan feature.

A simple test covering the happy path (e.g. `buildTransform(10, -5, 2, 0.5)` → `"translate(-50%, -50%) translate(10px, -5px) scale(4)"`) and the zero-fitScale guard would suffice.
