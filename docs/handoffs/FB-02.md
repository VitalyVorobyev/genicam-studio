# FB-02: Batch Apply

## Spec

**What:** An "Apply All" button in the Feature Browser toolbar that sequentially writes all pending draft values (skipping those with validation errors) to the device, with a progress strip showing N of M applied.
**Why:** Allows engineers to stage multiple parameter changes offline and commit them all with one click, which is essential for multi-parameter workflows like tuning exposure and gain simultaneously.

**Files touched:**
- `ui/genicam-studio-ui/src/components/FeatureBrowser/batchApplyUtils.ts` — new: `countApplicableDrafts` and `formatBatchProgress` pure functions
- `ui/genicam-studio-ui/src/components/FeatureBrowser/batchApplyUtils.test.ts` — new: unit tests for both pure functions
- `ui/genicam-studio-ui/src/components/FeatureBrowser/FeatureBrowserPage.tsx` — add `batchProgress` state + `handleBatchApply` async handler; "Apply All" button in toolbar; progress status strip; import and use both utilities

**Key decisions:**
- Writes are sequential (one-at-a-time), not parallel — camera nodes can have ordering constraints (e.g., Width before OffsetX); sequential is the safe default
- Drafts with validation errors are silently skipped; the skip count is not surfaced (the per-node error indicators already show them)
- On individual write failure, the draft is kept in state (not cleared) so the user can inspect and retry
- Progress state is `{ done: number; total: number } | null`; `null` means idle
- The "Apply All" button is disabled in offline mode (`!provider.applyNodeValue`), when there are no applicable drafts, and while applying
- Progress is shown as a `browser-status browser-status--info` strip (reusing existing style) below the toolbar, dismissed automatically when done
- No new CSS required — the existing `browser-status--info` covers the progress strip
