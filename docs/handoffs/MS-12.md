# MS-12: Node Interdependencies

## Spec

**What:** Simulate SFNC node side effects in the mock service — Width/Height changes clamp OffsetX/Y and update PayloadSize; PixelFormat changes update PayloadSize.
**Why:** Real cameras have these relationships. Without them the mock behaves unrealistically and UI tests cannot verify constraint propagation.

**Files touched:**
- `apps/genicam-mock-service/src/interdependencies.rs` — new module with pure side-effect logic
- `apps/genicam-mock-service/src/state.rs` — call `apply_side_effects` inside write lock; fix PayloadSize init
- `apps/genicam-mock-service/src/main.rs` — declare `mod interdependencies`
- `apps/genicam-mock-service/fixtures/sfnc-standard.xml` — add SensorWidth/SensorHeight RO nodes

**Key decisions:**
- Side-effect function is pure sync, takes `&mut HashMap` — executes inside existing write lock with no re-acquisition
- Falls back to `WidthMax`/`HeightMax` if `SensorWidth`/`SensorHeight` absent — defensive
- Returns `Vec<(String, Value)>` so caller broadcasts secondary changes via existing `change_tx`
- `PayloadSize` init uses explicit `PixelFormat::Mono8.bytes_per_pixel()` — documents the dependency

**Unit tests required:**
- `test_apply_side_effects_width_clamps_offset_x` — Width reduced, OffsetX exceeds new max → clamped
- `test_apply_side_effects_pixelformat_updates_payload` — PixelFormat changed → PayloadSize updated
- `test_apply_side_effects_height_clamps_offset_y` — Height reduced, OffsetY exceeds new max → clamped
