# IV-01: Image Viewer Layout Redesign

## Spec

**What:** Replace the minimal `ImageViewer.tsx` with a professional split layout — canvas column (toolbar strip + canvas + status bar) on the left, collapsible control sidebar with accordion sections on the right.

**Why:** Establishes the structural shell that every subsequent Image Viewer task (IV-02 through IV-17) fills in; the current single-canvas viewer has no room for controls.

**Files touched:**
- `ui/genicam-studio-ui/src/components/ImageViewer/ImageViewer.tsx` — rewritten as composition root; assembles sub-components
- `ui/genicam-studio-ui/src/components/ImageViewer/ViewerCanvas.tsx` — new; WebSocket + canvas rendering extracted from old ImageViewer; reports frame stats upward via callback
- `ui/genicam-studio-ui/src/components/ImageViewer/ViewerToolbar.tsx` — new; thin toolbar strip above canvas; placeholder for IV-12 controls
- `ui/genicam-studio-ui/src/components/ImageViewer/ViewerStatusBar.tsx` — new; thin bar below canvas showing resolution, pixel format, fps
- `ui/genicam-studio-ui/src/components/ImageViewer/ControlSidebar.tsx` — new; right sidebar shell; renders icon rail when collapsed
- `ui/genicam-studio-ui/src/components/ImageViewer/SidebarSection.tsx` — new; reusable accordion panel component
- `ui/genicam-studio-ui/src/components/ImageViewer/useViewerLayout.ts` — new; hook managing sidebar collapsed state with localStorage persistence
- `ui/genicam-studio-ui/src/components/ImageViewer/viewerUtils.ts` — new; pure utility functions (fitContain, formatFps, formatResolution)
- `ui/genicam-studio-ui/src/styles/tokens.css` — add four new tokens: `--iv-sidebar-width`, `--iv-sidebar-rail-width`, `--iv-toolbar-h`, `--iv-statusbar-h`
- `ui/genicam-studio-ui/src/styles/components.css` — append new `/* Image Viewer v2 */` section with all split-layout CSS rules; existing `.image-viewer` rules are preserved
- `CHANGELOG.md` — add entry under `[Unreleased]`

**Key decisions:**
- WebSocket frame rendering logic in `ViewerCanvas` is preserved verbatim from the current implementation; only the aspect-ratio calculation is moved to `fitContain()` in `viewerUtils.ts` — no behavioral change.
- `AppLayout.tsx` is unchanged: `<ImageViewer streamerInfo={streamerInfo} />` remains the call site; the new layout is self-contained.
- Sidebar collapse state is persisted in `localStorage` under key `"iv-sidebar-collapsed"` inside `useViewerLayout`; all `localStorage` calls are wrapped in `try/catch` (private-browsing guard).
- `SidebarSection` manages its own expand/collapse state for IV-01; state lifting for per-camera-model persistence (IV-10) is deferred deliberately.
- The four placeholder sections (Acquisition Control, Exposure & Gain, Image Format, Trigger Configuration) match ADR-006's default and available sections list; each body shows `"Available in a future update."` until the corresponding IV-0x task is implemented.
- `pixelFormat` in `ViewerStatusBar` is always `""` in this task; it will be wired from the `image-meta-changed` Tauri event in TB-01.
- No icon library is added; collapsed rail uses plain Unicode characters to avoid a new dependency.

### Important Issues

**I-1: Hardcoded pixel literals in new Image Viewer v2 CSS section**

Five hardcoded pixel values appear in the `/* Image Viewer v2 */` section of
`/Users/vitalyvorobyev/vision/genicam-studio/ui/genicam-studio-ui/src/styles/components.css`
(lines 1213, 1238, 1264, 1286, 1299), violating the project convention that all rules consume
tokens via `var(--*)`:

| Line | Rule | Value |
|------|------|-------|
| 1213 | `.iv-sidebar__toggle` | `font-size: 14px` |
| 1238 | `.iv-sidebar__rail-icon` | `font-size: 14px` |
| 1264 | `.sidebar-section__header` | `height: 36px` |
| 1286 | `.sidebar-section__icon` | `font-size: 13px` |
| 1299 | `.sidebar-section__chevron` | `font-size: 10px` |

Note: The pre-existing CSS below line 1121 contains the same pattern (e.g., `9px`, `10px`,
`11px` in `.log-entry__level`, `.tree-item__caret`, `.info__toggle-caret`), so this is a
widespread pre-existing convention rather than a strict block. However, the four new tokens added
in this task (`--iv-toolbar-h`, `--iv-statusbar-h`, `--iv-sidebar-width`, `--iv-sidebar-rail-width`)
show intent to tokenize; the icon/chevron font sizes and `.sidebar-section__header` height should
use existing tokens: `--text-sm` (12px ≈ closest to 13px; or add `--text-icon: 13px`),
`--text-xs` (11px; the 10px chevron would need a dedicated token), and `--iv-toolbar-h` for the
36px header height (which matches the existing `--iv-toolbar-h: 36px` token exactly).

Fix for `.sidebar-section__header { height: 36px; }`:
Replace with `height: var(--iv-toolbar-h);` — the value is already tokenized.
