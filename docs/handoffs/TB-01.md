# TB-01: Image Metadata Event

## Spec

**What:** Subscribe to `genicam/devices/{id}/image/meta` in the Tauri backend on device connect and emit an `image-meta-changed` Tauri event; add a `useImageMeta` hook in the UI that replaces the `liveValues.get("PixelFormat")` workaround in `ImageViewer.tsx`.

**Why:** Gives the frontend an authoritative, structured source for pixel format, image dimensions, and payload size — separate from the node-value stream — so `ViewerCanvas` pixel sampling and `ViewerStatusBar` display use the correct metadata even when the camera changes format mid-acquisition.

**Files touched:**
- `apps/genicam-studio-tauri/src-tauri/src/commands/device.rs` — add `spawn_image_meta_sub` function and include it in the per-connection task list inside `connect_device`
- `apps/genicam-studio-tauri/src-tauri/src/state/device_state.rs` — add `image_meta: Option<ImageMeta>` field to `AcquisitionInner`; add `get_image_meta` Tauri command helper (or inline it)
- `ui/genicam-studio-ui/src/device/types.ts` — add `ImageMeta` interface
- `ui/genicam-studio-ui/src/device/useImageMeta.ts` — new hook; listens for `image-meta-changed` and clears on disconnect
- `ui/genicam-studio-ui/src/components/Layout/AppLayout.tsx` — call `useImageMeta`, pass `imageMeta` prop to `ImageViewer`
- `ui/genicam-studio-ui/src/components/ImageViewer/ImageViewer.tsx` — accept `imageMeta` prop; derive `pixelFormat`, `width`, `height` from it; remove `liveValues.get("PixelFormat")` workaround

**Key decisions:**
- The `image/meta` subscription is a per-connection task (aborted on disconnect alongside `node_value`, `status`, and `acq_status`), consistent with all existing per-device subscribers. No global subscription is needed.
- `ImageMeta` is stored in `AcquisitionInner` so a `get_image_meta` IPC command could be added later (TB-02 era); for TB-01 the stored value is only used internally as a cache — the Tauri event is the delivery mechanism to the UI.
- The `PixelFormat` variant in `ImageMeta` is serialized as a JSON string (via `serde_json` default for the enum). The `image-meta-changed` event payload mirrors the Rust `ImageMeta` fields directly: `{ pixel_format: string, width: number, height: number, payload_size: number }`. This is a string, not the enum variant — safe for TypeScript.
- `ViewerStatusBar` and `ViewerCanvas` already accept `pixelFormat: string` props; no changes needed in those two files — only `ImageViewer.tsx` changes how it derives the value it passes down.
- When `imageMeta` is `null` (not yet received), fall back to `"Mono8"` as today, keeping the idle-state behaviour unchanged.

**Unit tests required:**
- No new pure Rust functions are introduced (the subscriber function is async I/O; `extract_node_name` is already tested). No new pure TS functions are introduced; the hook is event-driven. Therefore no new unit test functions are required by this task.
