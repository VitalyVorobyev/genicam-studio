# ZA-06: Node Constraints in Value Updates

## Spec

**What:** Extend `NodeValueUpdate` with optional `min`, `max`, `inc` fields so the camera service can report runtime numeric constraints alongside live values, and the UI can dynamically tighten slider ranges without re-parsing XML.
**Why:** Camera nodes change effective constraints at runtime (e.g., OffsetX max shrinks when Width increases); the UI currently uses only static XML-parsed min/max and has no mechanism to receive live constraint updates.

**Files touched:**
- `crates/genicam_zenoh_api/src/lib.rs` — add `min: Option<f64>`, `max: Option<f64>`, `inc: Option<f64>` (all `skip_serializing_if = "Option::is_none"`) to `NodeValueUpdate`; add `#[cfg(test)]` unit tests
- `apps/genicam-studio-tauri/src-tauri/src/state/device_state.rs` — add matching `min`, `max`, `inc` fields to the local `NodeValueEntry` struct
- `apps/genicam-studio-tauri/src-tauri/src/commands/device.rs` — populate the new fields when building `NodeValueEntry` from `NodeValueUpdate`; include them in the `node-value-changed` Tauri event payload
- `ui/genicam-studio-ui/src/device/types.ts` — add `min?: number`, `max?: number`, `inc?: number` to `NodeValueEntry` TypeScript interface
- `docs/zenoh-api.md` — update `nodes/{name}/value` payload examples and `node-value-changed` event table row

**Key decisions:**
- All three fields are `Option<f64>` (not separate integer/float variants) — the service already knows whether a node is Integer or Float; the UI receives both as JSON numbers and can apply `Math.round()` for integer sliders if needed
- `skip_serializing_if = "Option::is_none"` keeps payloads compact and maintains backward compatibility with old camera services that omit these fields
- The `NodeValueEntry` in `device_state.rs` is extended in parallel so the node cache always carries the latest constraints (the bulk-read path also benefits for free, as it reuses the same struct)
- No UI component changes in this task — the fields land in `NodeValueEntry` and are available to any component that reads `liveValues`; consuming them (e.g., updating sliders) is deferred to TB-04

**Unit tests required:**
- `test_node_value_update_without_constraints` in `lib.rs` — serializes without min/max/inc keys in output JSON
- `test_node_value_update_with_constraints` in `lib.rs` — round-trips with all three fields populated
- `test_node_value_update_deserializes_legacy` in `lib.rs` — legacy JSON (no min/max/inc) still deserializes with None values

**CHANGELOG entry:** `- ZA-06: NodeValueUpdate extended with optional min/max/inc constraint fields; NodeValueEntry carries runtime constraints to the UI`
