# IV-03: Exposure & Gain Section

## Spec

**What:** Adds the "Exposure & Gain" accordion section to the Image Viewer control sidebar, with slider + text-input controls for `ExposureTime` and `Gain`, and enum Auto toggles for `ExposureAuto` and `GainAuto` that disable the manual sliders when set to `"Continuous"`.

**Why:** Gives engineers direct, live control over the two most-used camera parameters from the Image Viewer without opening the full Feature Browser; completes the P0 sidebar controls for Milestone 3.

**Key decisions:**
- Writes happen on slider pointer-up and text-input blur only (not on every drag step), matching the pattern in `AcquisitionSection` and preventing write floods to the camera service.
- Draft state (`expDraft`, `gainDraft`) is local to the component and syncs from `liveValues` only when the user is not actively dragging (`dragging` ref gates sync). This prevents the slider from jumping while the user drags.
- Separate string state (`expText`, `gainText`) for the text input allows free typing; parse + clamp + commit happens on blur.
- Auto toggle is rendered only when `ExposureAuto` / `GainAuto` exists in the `UiGraph`; otherwise the row renders without the toggle (graceful degradation for cameras without auto functions).
- Fallback constraints: ExposureTime defaults to 100–100 000 µs; Gain defaults to 0.0–24.0 dB when the UiGraph node has no constraints.
- `ExposureGainSection` accepts no write callbacks — it calls `invoke("write_node", ...)` internally, identical to `AcquisitionSection`'s `handleModeChange` pattern.
- All new CSS uses `var(--*)` tokens exclusively; no hardcoded colours or sizes.
