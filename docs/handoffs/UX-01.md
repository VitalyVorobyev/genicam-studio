# UX-01: Design System (Tokens, Theme)

## Spec

**What:** Extract the existing CSS custom properties in `src/styles.css` into a dedicated `src/styles/tokens.css` file, add the missing token slots (warning/danger borders, kind-badge palette, bg-canvas, shadows, z-index scale, focus-ring, font weights, transitions), split component rules into `src/styles/components.css`, and replace every remaining hardcoded hex/rgba literal in the component rules with `var()` references.

**Why:** Every M3 Image Viewer task (IV-01 through IV-12) and UX-02/UX-05 will add new component CSS. A complete, split token system prevents value drift, makes the "Dark Instrument" aesthetic enforceable by convention, and gives future tasks a stable vocabulary to reference.

**Files touched:**
- `ui/genicam-studio-ui/src/styles/tokens.css` — CREATE: full `:root` token block with all existing + new tokens
- `ui/genicam-studio-ui/src/styles/components.css` — CREATE: all component rules from current `styles.css`, hardcoded values replaced with `var()`
- `ui/genicam-studio-ui/src/styles.css` — MODIFY: becomes a two-line shim (`@import "./styles/tokens.css"; @import "./styles/components.css";`)
- `CHANGELOG.md` — MODIFY: add entry under `[Unreleased]`

**Key decisions:**
- Single global CSS file structure (no CSS modules, no Tailwind, no styled-components) — the existing approach is already correct; UX-01 only adds structure within it.
- New tokens to add: `--warning-border`, `--danger-border`, `--kind-integer/boolean/string/enum/command` (with `-muted`/`-border` variants), `--bg-canvas` (#080c10 for image viewer), `--fw-regular/medium/semibold/bold`, `--lh-tight/base/loose`, `--transition-fast/base/slow`, `--shadow-sm/md/lg`, `--overlay-bg`, `--focus-ring`, `--focus-ring-muted`, `--z-base/dropdown/overlay/toast`.
- The `@import` shim in `styles.css` works natively with Vite — no config change needed.
- No TypeScript theme constants object in UX-01 scope; canvas 2D color needs (IV-12 pixel inspector) deferred to that task.

**Unit tests required:** None — pure CSS, no TypeScript functions introduced.

**Important — bare `rgba()` literal at `components.css:371`:**
```css
background: linear-gradient(135deg, var(--bg-elevated) 0%, rgba(63, 185, 80, 0.05) 100%);
```
A 5%-opacity success-green tint (`rgba(63, 185, 80, 0.05)`) is not captured by any token.
`--success-muted` (12%) and `--success-border` (40%) exist, but 5% does not.
Fix: add `--success-tint: rgba(63, 185, 80, 0.05)` to `tokens.css` and replace the literal,
or accept as a one-off intentional gradient stop (low risk, aesthetic only).

**Observation — sub-scale raw pixel sizes in `components.css` (lines 174, 431, 583, 584, 759, 1055, 1091):**
Values of 9 px, 10 px, 11 px, 18 px are used for decorative icons and badges.

of hardcoded colour values, so these are out of scope for UX-01 but worth capturing
for a future UX-03 type-scale cleanup.
