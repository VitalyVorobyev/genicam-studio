# TB-03: SFNC Groups Config Loader

## Spec

**What:** Bundle a `sfnc-groups.json` config file with the Tauri app, expose it via a cached IPC command `get_sfnc_groups() -> Vec<SfncGroup>`, and add a `useSfncGroups` React hook that loads the config once on mount.

**Why:** IV-09 (SFNC groups runtime mapping) requires a static config that maps Image Viewer sidebar sections to SFNC node names and widget hints; without this loader there is no source of truth for which nodes belong to which section.

**Files touched:**

- `apps/genicam-studio-tauri/src-tauri/tauri.conf.json` — add `bundle.resources` array to bundle the JSON file
- `apps/genicam-studio-tauri/src-tauri/src/commands/sfnc_groups.rs` — new file: `SfncGroup`/`SfncFeature` structs, `parse_sfnc_groups` pure helper, `SfncGroupsState` type alias, `get_sfnc_groups` Tauri command
- `apps/genicam-studio-tauri/src-tauri/src/commands/mod.rs` — add `pub mod sfnc_groups`
- `apps/genicam-studio-tauri/src-tauri/src/main.rs` — construct `SfncGroupsState`, add `.manage()`, register command in `generate_handler!`
- `ui/genicam-studio-ui/src/device/types.ts` — append `SfncFeature` and `SfncGroup` TypeScript interfaces
- `ui/genicam-studio-ui/src/device/useSfncGroups.ts` — new hook: calls `get_sfnc_groups` once, returns `SfncGroup[]`

**Key decisions:**
- `parse_sfnc_groups(bytes: &[u8]) -> Result<Vec<SfncGroup>, String>` is extracted as a pure function (no I/O, no async) so it can be unit-tested without a Tauri app handle; the command itself stays thin.
- Caching uses `Arc<RwLock<Option<Vec<SfncGroup>>>>` in Tauri managed state; the command does a read-lock fast path on every call after the first, writing only on the first miss. A double-read race on first call is harmless — worst case the file is read twice; both parses produce identical results.
- `SfncFeature.widget` is `String` in Rust (not an enum) to preserve forward compatibility: a new widget kind added to the JSON in a future update will not cause a parse failure in an already-compiled binary. The TypeScript `widget` field is a literal union type to give IV-09 implementers compile-time coverage of all known widget kinds.
- `std::fs::read` (blocking) is used inside the async command because this is a one-time cold-path read of a small bundled file; `tokio::fs::read` can replace it later if strict async hygiene is required.
- Resource is accessed via `app.path().resolve("resources/sfnc-groups.json", tauri::path::BaseDirectory::Resource)` — the Tauri v2 API for files listed in `bundle.resources`.
- Field name `default_open` (not `default_expanded` as sketched in ADR-007) because serde `snake_case` maps it cleanly to `defaultOpen` in TypeScript without manual renaming.

**Unit tests required:**
- `fn test_parse_sfnc_groups_happy_path` in `commands/sfnc_groups.rs` — one group, two features; id/title/icon/default_open/node names all match
- `fn test_parse_sfnc_groups_empty_groups` in `commands/sfnc_groups.rs` — `{"groups":[]}` returns `Ok(vec![])`
- `fn test_parse_sfnc_groups_invalid_json` in `commands/sfnc_groups.rs` — `b"not json"` returns `Err` containing `"Failed to parse sfnc-groups.json"`
- `fn test_parse_sfnc_groups_missing_groups_key` in `commands/sfnc_groups.rs` — `{"items":[]}` returns `Err` (missing required field)
- `fn test_parse_sfnc_groups_unknown_widget_string` in `commands/sfnc_groups.rs` — `"widget":"custom_widget"` parses successfully (Rust does not reject unknown widget strings)

The implementation note in the spec acknowledges this and calls it acceptable for a one-time cold-path read of a small bundled file.  No action required for TB-03; a future ticket can replace it with `tokio::fs::read` if strict async hygiene is introduced.
