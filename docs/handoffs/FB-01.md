# FB-01: Live Value Display in Tree

## Spec

**What:** Show the live node value inline in each category tree row (replacing the kind-label meta area) when a live value is available, and in search result rows, so engineers can glance at current device state without clicking into the detail panel.
**Why:** Currently live values are only visible in the right-hand FeaturePanel; the tree requires a click per node to see the current value, which is slow when scanning many parameters.

**Files touched:**
- `ui/genicam-studio-ui/src/components/FeatureBrowser/treeUtils.ts` — new: `formatLiveValue(entry: NodeValueEntry): string` pure function
- `ui/genicam-studio-ui/src/components/FeatureBrowser/treeUtils.test.ts` — new: unit tests for `formatLiveValue`
- `ui/genicam-studio-ui/src/components/FeatureBrowser/CategoryTree.tsx` — add `liveValues` prop; thread through to `CategoryTreeNode`
- `ui/genicam-studio-ui/src/components/FeatureBrowser/CategoryTreeNode.tsx` — add `liveValues` prop; render `tree-item__live` span with formatted value for leaf nodes when live value is present
- `ui/genicam-studio-ui/src/components/FeatureBrowser/FeatureBrowserPage.tsx` — pass `liveValues` to `CategoryTree`; render live value in `SearchResults` rows
- `ui/genicam-studio-ui/src/styles/components.css` — `.tree-item__live` (success color, mono, max-width, ellipsis overflow)

**Key decisions:**
- When live value is present for a leaf node, the `tree-item__meta` (kind label) is replaced by a `tree-item__live` span in success green — the kind is already communicated by the colored icon, so hiding the label maintains row width and reduces visual clutter
- `formatLiveValue` treats numbers as: integer → `String(n)`, float → `n.toFixed(3)` with trailing zeros stripped; this keeps values short enough to fit in the tree
- `liveValues` is passed as optional (`Map<string, NodeValueEntry> | undefined`) so `CategoryTree` continues to work in WASM/browser mode where live values are never set
- Category rows never show live values (they have no direct value in the device)
- Search results use the same `formatLiveValue` and show a `tree-item__live` span after the node name
