# ZA-05: API Version Negotiation

## Spec

**What:** Add an `api_version` field to `DeviceAnnounce`, define a shared `API_VERSION` constant, update the mock service to include it, and check compatibility in the Tauri discovery loop with a warning event on mismatch.

**Why:** Allows future camera services to signal their protocol version so the app can warn users about incompatible services before attempting a connection.

**Files touched:**
- `crates/genicam_zenoh_api/src/lib.rs` — add `API_VERSION: u32 = 1` constant; add `api_version: Option<u32>` with `#[serde(default)]` to `DeviceAnnounce`
- `apps/genicam-mock-service/src/discovery.rs` — set `api_version: Some(API_VERSION)` in published announce
- `apps/genicam-studio-tauri/src-tauri/src/state/device_state.rs` — add `ApiVersionMismatch` event payload struct
- `apps/genicam-studio-tauri/src-tauri/src/commands/device.rs` — add `check_api_version` pure function; call it in discovery loop; emit `api-version-mismatch` Tauri event on missing or incompatible version
- `docs/zenoh-api.md` — document `api_version` field in `DeviceAnnounce` section and new `api-version-mismatch` Tauri event

**Key decisions:**
- `api_version` is `Option<u32>` with `#[serde(default)]` so old services (without the field) deserialize to `None` and are not rejected — only warned.
- Soft-incompatibility: both missing and mismatched versions emit `api-version-mismatch` but still allow discovery so the user can decide.
- `API_VERSION = 1` is the first versioned release.
- The check is simple integer equality — same integer = compatible; no semver complexity needed at this scale.

**Unit tests required:**
- `fn test_check_api_version_compatible` in `device.rs` — same version returns `Compatible`
- `fn test_check_api_version_missing` in `device.rs` — `None` returns `Missing`
- `fn test_check_api_version_incompatible` in `device.rs` — different version returns `Incompatible(n)`
- `fn test_device_announce_deserializes_without_api_version` in `genicam_zenoh_api` — legacy JSON (no `api_version` field) deserializes with `api_version: None`
- `fn test_device_announce_deserializes_with_api_version` in `genicam_zenoh_api` — JSON with `api_version` deserializes correctly

**CHANGELOG entry:** `- ZA-05: API version negotiation — api_version field in DeviceAnnounce; compatibility check on discovery; api-version-mismatch Tauri event`
