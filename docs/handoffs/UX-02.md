# UX-02: App Header & Navigation

## Spec

**What:** Restructure the app header into a three-zone 48px bar — left wordmark, center tab bar, right device-status chip + acquisition indicator — and introduce a pure utility module for header-specific display logic.

**Why:** The current header mixes brand, device name, and action buttons in a two-zone layout that becomes visually cluttered when acquiring; a professional three-zone layout lets users monitor device and acquisition state from any tab without navigating.

**Files touched:**
- `ui/genicam-studio-ui/src/components/Layout/AppLayout.tsx` — restructure JSX into three-zone header layout; move tab bar from `.main-tabs` block into the header center zone
- `ui/genicam-studio-ui/src/components/Layout/headerUtils.ts` — new file; pure functions: `formatDeviceChip` and `truncateDeviceName`
- `ui/genicam-studio-ui/src/components/Layout/headerUtils.test.ts` — new file; unit tests for the two pure functions above
- `ui/genicam-studio-ui/src/styles/tokens.css` — update `--header-h` from `44px` to `48px`; remove now-redundant `--tab-h` usage inside header (keep `--tab-h` for potential future use)
- `ui/genicam-studio-ui/src/styles/components.css` — replace `.app-header` block, `.app-header__*` sub-rules, `.main-tabs`, `.main-tab`, `.main-tab--active`, `.main-tab__live-dot` blocks, add new `.app-header__tabs`, `.app-header__device-chip`, `.app-header__acq-indicator` rules

**Key decisions:**
- The tab bar moves into the header center zone rather than sitting below the header; this eliminates the separate 36px tab strip, reclaiming vertical space, and makes the three-zone layout possible.  The `.main-tabs` DOM element and its CSS block are removed; tabs become `.app-header__tabs` inside the `<header>`.
- Device status is expressed as a chip (dot + label) rather than appending the name to the brand wordmark; this is visually cleaner and works with all four `ConnectionState` variants without restructuring the brand area.
- The acquisition indicator (pulsing red dot + "Acquiring" label + Stop button) is only rendered when `acqStatus.active === true`; zero DOM presence when idle keeps the header clean.
- `truncateDeviceName` is a pure function with a configurable `maxLen` (default 22 chars); it lives in `headerUtils.ts` so it is independently testable with no JSX or async dependencies.
- The `--header-h` token is the single source of truth for height; changing it from `44px` to `48px` propagates to the `<header>` height rule, body offset, and any consumers that read the token.
- No state is added; all props (`isConnected`, `acqStatus`, `connectionState`, `handleStartAcquisition`, `handleStopAcquisition`) already exist in `AppLayoutInner`.

**Unit tests required:**
- `test_truncate_short_name_unchanged` in `headerUtils.test.ts` — name under limit passes through unchanged
- `test_truncate_long_name_ellipsis` in `headerUtils.test.ts` — name over limit is truncated to `maxLen` chars + ellipsis
- `test_truncate_exact_boundary` in `headerUtils.test.ts` — name exactly at limit is not truncated
- `test_format_chip_connected` in `headerUtils.test.ts` — returns `{ label, state: "connected" }` with truncated name
